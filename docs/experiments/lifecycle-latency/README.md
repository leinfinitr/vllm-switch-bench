# Lifecycle latency experiment

## Question

Across the retained single-node, single-GPU model matrix, how long do distinct model
**sleep** and **wake** lifecycle boundaries take for Proposed, vLLM L1, vLLM L2,
SwapServeLLM, and llama-swap?

## Metric

The primary metrics are `sleep_s` and `wake_s`, reported independently as the median and
interquartile range (Q1–Q3) across five valid cycles for each of three model sizes. A cycle
is valid only when both phase durations are finite and positive and the retained functional
output matches where that field is available.

For vLLM and SwapServeLLM, the values are explicit lifecycle operation durations. For
llama-swap, sleep and wake are source-instrumented process-state intervals, not its complete
request latency. The figure uses a logarithmic y-axis. Sleep plus wake is not reported as a
new metric here.

## Method

The retained matrix covers `qwen-0.5b`, `qwen-1.5b`, and `qwen-3b`, five cycles per
model/system/phase. The builder reads family raw JSON, filters llama-swap rows by model,
recomputes Q1/median/Q3, and writes 30 aggregate cells to JSON/CSV plus the figure. The
validator requires the exact 3 × 5 × 2 matrix, five samples per cell, finite positive values,
output equality where recorded, exact external executable contracts, and byte-for-byte
raw-to-summary recomputation.

External SwapServeLLM and profiled llama-swap executables are referenced by immutable
`v0.1.8` release URLs, byte sizes, and SHA-256 values in result metadata. Those digests bind
artifacts outside Git and remain part of the experiment contract.

## Retained result

The retained medians show Proposed sleep/wake at approximately 0.051/0.292 s for 0.5B,
0.106/0.337 s for 1.5B, and 0.157/0.477 s for 3B. vLLM L1 wake medians are similar in this
observation, while vLLM L2 wake increases from about 0.431 to 1.478 s across the model
sizes. SwapServeLLM medians range from 0.441–0.931 s for sleep and 0.432–1.017 s for wake.
The instrumented llama-swap wake interval is much larger (about 11.273–13.276 s).

These are retained descriptive observations, not a new comparative claim generated by this
refactor.

## Threats to validity

- Only one local single-GPU environment and three Qwen model sizes are represented.
- Five cycles per cell support descriptive medians/IQRs, not broad inferential claims.
- Page-cache, allocator state, warmup, CUDA graph behavior, and external process startup can
  materially affect boundaries.
- Systems expose different native mechanisms; source-instrumented process transitions are
  not semantically identical to in-process allocator sleep/wake.
- The logarithmic figure makes orders of magnitude visible but can visually compress small
  absolute differences.

## Limitations

No canonical GPU rerun is complete, and no new data was generated during the refactor. The
retained v0.1 producer provenance does not satisfy the current runtime-binding standard for
all rows. In particular, the related E2E campaign did not runtime-bind engine/controller
commits, actually imported path, or configuration hash; treat it as a historical local
observation. Rebuilding this family proves deterministic interpretation of retained bytes,
not exact recreation of the original runtime.

ServerlessLLM is not in this current numeric family because its automatic scale-to-zero
contract was not established. Results do not establish throughput, concurrency behavior,
cluster behavior, energy, or a universal ranking.

## Reproduce

### Deterministic CPU rebuild and validation

From the repository root:

```bash
uv sync --frozen --group dev
scripts/build_all.sh
uv run python -m llm_switch_bench.validation.lifecycle_latency.validate
scripts/validate_all.sh
git diff --exit-code -- results/lifecycle-latency
```

Repeat the build/validation/diff sequence once more to verify clean deterministic output.
This path uses retained raw evidence and does not run a GPU benchmark.

### Live measurement (GPU; not run in this refactor)

```bash
scripts/lifecycle-latency.sh \
  --model /path/to/model \
  --workdir /path/to/vllm \
  --python /path/to/vllm-python \
  --methods sleep_l1 sleep_l2 \
  --prompts short_short \
  --repeats 5 \
  --out-dir results/tmp/lifecycle-latency
```

Before promotion, bind the benchmark and actual engine/controller source identities,
imported package path, configuration digest, model revision, executable/image digest,
CUDA/driver/GPU, phase boundaries, and functional/post-resource conditions.
